# 快速识别优化验证

本文为0.2.0自制OCR的历史基准。0.3.0已替换为未修改的官方原生worker，下列成功率不适用于当前版本，详见 [官方组件接入](OCR-COMPARISON.md)。

2026-10-18，Windows x64固定测试环境。固定原版为提交 `f27807f8c93f3cc50525cfd9051f70d5bcd65c72`，对照读取其原始裁剪及OCR实现，使用同一个离线英文模型。

## 方法与结果

历史命令为 `npm run test:ocr-benchmark`（当前已移除）。Chromium Canvas生成固定清晰、小字、低对比度和模糊样本，并裁剪本地私有游戏截图；额外生成缩小、模糊、JPEG压缩、整条输入框、输入框加复制按钮和更大边距版本。截图和实际邀请码仅本地保存，不随仓库上传。

总计 26 个不同样本。4 个清晰样本各重复 7 次，其余各 1 次，共 50 轮/版本。引擎分别预热两轮；同一清晰样本的新旧版本交替顺序测量。每轮按至少 100ms 的采样间隔最多处理 8 帧，使用原有置信度80及至少150ms稳定窗口。优化版按选区形状选择单行或稀疏文字模式，并从码字边界读取置信度；低于门槛时最多再做一次放大复核。两个版本串行运行。

| 指标 | 原版 | 优化版 |
| --- | ---: | ---: |
| 清晰样本热启动确认中位耗时 | 232.17ms | 232.46ms |
| 不同样本正确确认 | 19/26 | 24/26 |
| 模糊样本正确确认 | 8/11 | 10/11 |
| 全部50轮正确确认 | 43/50 | 48/50 |
| 宽选区正确确认 | 1/3 | 3/3 |
| 错误确认 | 0 | 0 |
| 用户游戏截图及4种降质版本 | 5/5 | 5/5 |

清晰码速度基本持平，满足不增加超过10%的要求。三个宽选区原版只确认1个；优化版全部确认，热启动后确认耗时为251-269ms。小字、模糊 `HKM246` 和模糊 `XYZ789` 有增益，没有样本从原版正确退化为新版错误。逐帧识别文本、置信度、处理模式和耗时保存在 `artifacts/ocr-benchmark.json`。

## 回归与边界

- 合成的低对比度 `ABC123` 和1.1px模糊的 `XYZ789` 两版均未确认。低置信度结果不自动复制或加入。
- 上述耗时包括测试采样等待、Canvas裁剪和PNG传输、真实OCR及确认判断，排除引擎冷启动。它是固定本机基准，不是直播端到端延迟承诺。
- 本地游戏截图已通过Electron播放器完整流程：编码为H.264视频、拖动框选整条输入框、正确识别和剪贴板回读；证据仅本地保存。
- `npm run test:recognition` 在真实UI/IPC中延迟OCR结果，验证窗口隐藏时继续处理、码字复核途中停止不会写入剪贴板，以及换会话、换选区后旧结果不进入预处理状态。
- `npm run test:presets` 验证区域预设保存、自动应用、手动应用、参考框开关和设置持久化。

参考软件的原生OCR worker不提供可复用的CIL或脚本，本实现没有调用其私有二进制。此次改进独立采用单词边界置信度、宽选区定位、码字二次放大、反锐化和对比度增强。仅使用固定样本和离线测试；真实直播的动态压缩、不同字体和严重模糊仍需进一步采样。
